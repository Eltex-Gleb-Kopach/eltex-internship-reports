Функция `main()` является точкой входа в программу. Она принимает количество
аргументов `argc` и массив аргументов `argv`, переданных пользователем при
запуске. Затем мы объявляем переменную `options` типа
`struct program_options`.

После этого вызываем функцию `parse_arguments()`, передавая ей `argc`, `argv`
и адрес переменной `options`. Функция проверяет аргументы и записывает в
структуру настройки программы: имя FIFO и индекс первого файла.

Если `parse_arguments()` успешно проверила аргументы и вернула `0`, функция
`main()` вызывает `run_file_copy()`. Это основная функция программы: она
создаёт каналы, порождает дочерний процесс и запускает передачу файлов между
родителем и ребёнком. В неё передаются адрес заполненной структуры `options`,
количество аргументов `argc` и массив аргументов `argv`.

В функции `run_file_copy()` создаются два массива для хранения файловых
дескрипторов каналов. Массивы сами не создают каналы. В элементе с индексом
`0` хранится дескриптор чтения, а в элементе с индексом `1` — дескриптор
записи.

`ready_pipe` используется для передачи сообщения `READY` от дочернего
процесса родительскому. Это сообщение означает, что ребёнок готов принимать
данные. `data_pipe` используется в обратном направлении: через него родитель
передаёт ребёнку служебные сообщения, сведения о файлах и их содержимое.

Сначала с помощью `pipe()` создаётся канал `ready_pipe`. При успехе функция
`pipe()` возвращает `0` и записывает в массив дескрипторы чтения и записи.
Затем проверяется наличие имени FIFO.

Если имя отсутствует, значит ключ `-p` не использовался, и программа создаёт
неименованный канал `data_pipe`. Если создать его не удалось, выводится
ошибка, закрываются оба дескриптора ранее созданного `ready_pipe`, после чего
программа возвращает `EXIT_FAILURE`.

Если `options->channel_name` не равен `NULL`, значит пользователь передал ключ
`-p` и имя FIFO. Тогда вызывается функция `create_fifo_channel()`, которая
создаёт именованный канал и записывает его дескрипторы чтения и записи в
массив `data_pipe`.

Если `create_fifo_channel()` возвращает `-1`, продолжать работу невозможно.
Поэтому закрываются оба конца ранее созданного `ready_pipe`, и программа
возвращает `EXIT_FAILURE`. Если ошибка произошла внутри
`create_fifo_channel()`, эта функция сама закрывает уже открытые ею
дескрипторы FIFO и удаляет созданный файл FIFO.

Функция `create_fifo_channel()` получает имя FIFO и массив, в который будут
записаны дескрипторы чтения и записи. С помощью `mkfifo()` создаётся
специальный файл именованного канала с правами чтения и записи только для
владельца.

В специальном файле FIFO дескрипторы не хранятся. `mkfifo()` создаёт имя FIFO
в файловой системе, а файловые дескрипторы появляются после вызова `open()` и
хранятся в таблице открытых файлов процесса.

Затем FIFO открывается для чтения, и полученный дескриптор записывается в
`fifo_fds[0]`. Поскольку оба конца открываются одним процессом до `fork()`,
читающий конец временно открывается с флагом `O_NONBLOCK`, чтобы программа не
остановилась в ожидании писателя.

После этого FIFO открывается для записи, а полученный дескриптор сохраняется
в `fifo_fds[1]`. Когда оба конца открыты, функция с помощью `fcntl()` убирает
`O_NONBLOCK` с читающего дескриптора, возвращая чтение в обычный блокирующий
режим. Сам FIFO при этом не удаляется.

С помощью `fork()` создаётся дочерний процесс. Если функция вернула `-1`,
создание завершилось ошибкой. Тогда программа закрывает все ранее созданные
дескрипторы, при необходимости удаляет FIFO и возвращает `EXIT_FAILURE`.

Если `fork()` вернула `0`, код выполняется в дочернем процессе. Ребёнок
закрывает неиспользуемый читающий конец `ready_pipe` и записывающий конец
`data_pipe`. Затем вызывается функция `run_child()`, которой передаются
дескриптор записи сообщения `READY` и дескриптор чтения данных от родителя.

В функции `run_child()` создаётся константный массив символов
`ready_message`, содержащий строку `"READY"`. Затем ребёнок выводит
собственный PID и PID родительского процесса.

После этого с помощью `write_all()` сообщение `READY` полностью записывается
в `ready_pipe`, чтобы сообщить родителю о готовности принимать данные. Если
`write_all()` возвращает `-1`, ребёнок выводит ошибку, закрывает принадлежащие
ему дескрипторы и возвращает `EXIT_FAILURE`.

После успешной отправки сообщения ребёнок закрывает записывающий дескриптор
`ready_pipe`, потому что больше ничего через этот канал отправлять не будет.
Закрывается именно дескриптор записи, а не весь канал.

После отделения ветки ребёнка выполнение продолжается в родительском
процессе. Родитель закрывает записывающий конец `ready_pipe`, потому что через
этот канал он только читает, и читающий конец `data_pipe`, потому что через
него он только записывает.

Затем вызывается `run_parent()`, которой передаются PID ребёнка, дескриптор
чтения `ready_pipe`, дескриптор записи `data_pipe`, указатель на структуру
`options`, количество аргументов `argc` и массив аргументов `argv`.

В `run_parent()` создаётся массив `received_message`, размер которого равен
размеру строки `"READY"` вместе с завершающим нулём. Затем родитель вызывает
`read_all()` и блокируется в ожидании сообщения от ребёнка. Функция читает
байты из `ready_pipe`, записывает их в массив и возвращает количество
полученных байтов.

Родитель проверяет результат `read_all()`. Если функция вернула `-1`,
произошла ошибка чтения сообщения `READY`. Родитель выводит ошибку, закрывает
дескрипторы чтения `ready_pipe` и записи `data_pipe`, затем через
`wait_for_child()` дожидается завершения ребёнка, чтобы корректно забрать его
статус, и возвращает `EXIT_FAILURE`.

Если чтение завершилось без системной ошибки, родитель закрывает дескриптор
чтения `ready_pipe`, потому что сообщение уже находится в массиве
`received_message` и этот канал больше не понадобится.

Затем проверяется, что сообщение получено полностью и действительно равно
`"READY"`. Если сообщение неправильное, родитель закрывает дескриптор записи
`data_pipe`, дожидается завершения дочернего процесса через
`wait_for_child()`, забирает его статус, чтобы ребёнок не остался
зомби-процессом, и возвращает `EXIT_FAILURE`.

После успешной проверки `READY` родитель печатает полученное сообщение, а
затем выводит собственный PID и PID ребёнка. Далее он проверяет
`options->channel_name` и сообщает, какой режим используется. Если значение
равно `NULL`, используется неименованный канал. Если имя присутствует,
используется именованный FIFO.

После этого начинается цикл, который последовательно перебирает все имена
файлов, переданные пользователем. Перебор начинается с индекса
`options->first_file_index` и продолжается, пока `file_index` меньше `argc`.

Внутри цикла создаётся указатель `file_name`, который указывает на строку с
именем текущего файла в массиве `argv`. Затем функция `open()` открывает этот
файл только для чтения и возвращает его файловый дескриптор.

Если открыть файл не удалось, родитель выводит ошибку, закрывает дескриптор
записи `data_pipe`, дожидается завершения ребёнка и возвращает
`EXIT_FAILURE`.

После успешного открытия объявляется переменная `source_info` типа
`struct stat`. Эта структура хранит различную информацию о файле, включая
его размер, права и тип. Функция `fstat()` получает информацию об уже
открытом файле по его дескриптору и записывает её в `source_info`.

Если `fstat()` завершилась ошибкой, родитель закрывает дескриптор исходного
файла, закрывает дескриптор записи `data_pipe`, дожидается завершения ребёнка
и возвращает `EXIT_FAILURE`.

Если информация получена успешно, родитель печатает имя открытого файла и
его размер из поля `source_info.st_size`.

Далее создаётся переменная `metadata` типа `struct file_metadata`. При помощи
`{0}` все её поля первоначально обнуляются, после чего полю `type`
присваивается значение `MESSAGE_FILE`. Это значение сообщает ребёнку, что
структура описывает очередной файл, после которой будет передано его
содержимое.

Значение `MESSAGE_FILE` означает не то, что файл является не последним, а то,
что текущее служебное сообщение содержит сведения о файле. Даже перед
последним файлом отправляется `MESSAGE_FILE`. После передачи всех файлов
родитель отдельно отправит сообщение `MESSAGE_DONE`.

Затем с помощью `strlen()` вычисляется длина имени файла. К результату
прибавляется `1`, чтобы учесть завершающий символ строки `\0`. После этого
проверяется, помещается ли имя в массив `metadata.file_name`.

Если имя слишком длинное, родитель закрывает дескриптор исходного файла и
дескриптор записи `data_pipe`, дожидается завершения ребёнка и возвращает
`EXIT_FAILURE`.

Если имя помещается в массив, функция `memcpy()` копирует его в поле
`metadata.file_name`. Через `memcpy()` копируется только имя файла. Размер
файла отдельно записывается в поле `metadata.file_size` из
`source_info.st_size`.

После заполнения структуры `metadata` родитель с помощью `write_all()`
передаёт её дочернему процессу через дескриптор записи `data_pipe`. В функцию
передаются дескриптор канала, адрес структуры `metadata` и полный размер этой
структуры в байтах.

Затем проверяется результат `write_all()`. Если функция вернула `-1`,
родитель выводит ошибку, закрывает исходный файл и дескриптор записи
`data_pipe`, дожидается завершения ребёнка и возвращает `EXIT_FAILURE`.

Если структура успешно передана, родитель печатает сообщение с именем и
размером отправляемого файла. На этом этапе передаются только метаданные: тип
сообщения, имя файла и его размер. Само содержимое файла будет отправлено
следующим действием через `send_file_content()`.

Затем родитель вызывает `send_file_content()`, которая передаёт содержимое
файла ребёнку блоками. В функцию передаются дескриптор открытого исходного
файла, дескриптор записи в канал и размер файла из поля
`metadata.file_size`. Вся структура `metadata` в эту функцию не передаётся.

Результат передачи сохраняется в переменной `send_result`. После возвращения
из функции исходный файл закрывается. Затем отдельно проверяется, успешно ли
закрылся файл и удалось ли `send_file_content()` передать всё его содержимое.

Функция `send_file_content()` читает исходный файл частями и передаёт
прочитанные байты ребёнку через канал. Она получает дескриптор исходного
файла `source_fd`, дескриптор записи в канал `data_write_fd` и размер файла
`file_size`, ранее полученный через `fstat()`.

Внутри функции создаётся временный массив `buffer` размером
`DATA_BUFFER_SIZE`, то есть 4096 байтов. Весь файл сразу в память не
загружается. Содержимое по очереди читается в этот буфер и отправляется в
канал.

Переменная `bytes_remaining` первоначально равна полному размеру файла и
хранит количество байтов, которые ещё осталось передать. Цикл работает,
пока `bytes_remaining` больше нуля. Для пустого файла это условие сразу
ложно, поэтому цикл не выполняется и функция возвращает успешный результат.

На каждой итерации вычисляется `requested_size` — количество байтов, которое
нужно прочитать следующим вызовом `read()`. Если осталось не меньше размера
буфера, запрашивается весь буфер. Если остался последний блок меньшего
размера, запрашивается только фактический остаток файла.

Переменная `bytes_read` хранит количество байтов, которое фактически вернула
функция `read()`. `read()` читает данные из `source_fd` и записывает их в
`buffer`. Если системный вызов был прерван сигналом и `errno` равен `EINTR`,
чтение повторяется.

Если `read()` возвращает `-1`, произошла ошибка чтения, поэтому функция
выводит диагностическое сообщение и возвращает `EXIT_FAILURE`.

Если `read()` возвращает `0`, хотя по размеру из `fstat()` данные ещё должны
оставаться, файл закончился раньше ожидаемого. Такое возможно, если его
уменьшили во время копирования. Этот случай также считается ошибкой.

Успешно прочитанный блок передаётся ребёнку через `write_all()`. В неё
передаются дескриптор записи `data_write_fd`, адрес буфера и фактическое
количество прочитанных байтов. `write_all()` гарантирует запись всего блока
в канал.

После отправки блока из `bytes_remaining` вычитается `bytes_read`. Цикл
повторяется, пока количество оставшихся байтов не станет равным нулю. После
передачи количества байтов, указанного в `file_size`, функция возвращает
`EXIT_SUCCESS`.

После возвращения из `send_file_content()` родитель закрывает дескриптор
исходного файла. Если закрыть файл не удалось, родитель выводит ошибку,
закрывает дескриптор записи `data_pipe`, дожидается завершения ребёнка и
возвращает `EXIT_FAILURE`.

Затем проверяется результат `send_file_content()`. Если содержимое передать
не удалось, родитель закрывает дескриптор записи `data_pipe`, дожидается
завершения ребёнка и возвращает `EXIT_FAILURE`.

Если всё прошло успешно, родитель печатает количество отправленных байтов.
После этого цикл переходит к следующему имени файла из `argv`. Так
продолжается, пока не будут обработаны все переданные пользователем файлы,
включая последний.

После выхода из цикла создаётся переменная `done_message` типа
`struct file_metadata`, и все её поля обнуляются. Полю `type` присваивается
значение `MESSAGE_DONE`. Это служебное сообщение означает, что новых файлов
больше не будет.

Затем вся структура `done_message` отправляется ребёнку через `write_all()`.
В функцию передаются дескриптор записи `data_pipe`, адрес структуры и её
полный размер в байтах.

Если отправить `MESSAGE_DONE` не удалось, родитель закрывает дескриптор
записи `data_pipe`, дожидается завершения ребёнка и возвращает ошибку.

Если сообщение успешно отправлено, родитель печатает, что все файлы
переданы, и закрывает записывающий дескриптор `data_pipe`. После этого он
вызывает `wait_for_child()`, блокируется до завершения ребёнка, забирает его
статус и возвращает результат его работы.

После отправки `READY` ребёнок входит в бесконечный цикл. Цикл нужен, потому
что родитель может передать несколько файлов. На каждой итерации ребёнок
ожидает очередное служебное сообщение.

Внутри цикла создаётся переменная `received_metadata` типа
`struct file_metadata`. Функция `read_all()` читает из `data_pipe` полную
структуру и записывает полученные байты в `received_metadata`.

Сначала проверяется результат чтения. Значение `-1` означает системную
ошибку. Если получено меньше байтов, чем занимает `received_metadata`,
служебное сообщение пришло не полностью. В обоих случаях ребёнок закрывает
дескриптор чтения `data_pipe` и возвращает `EXIT_FAILURE`.

После успешного чтения проверяется тип сообщения. Если получен
`MESSAGE_DONE`, ребёнок печатает сообщение и выходит из бесконечного цикла
через `break`.

Если тип не равен ни `MESSAGE_DONE`, ни `MESSAGE_FILE`, получено неизвестное
служебное сообщение. Ребёнок закрывает дескриптор чтения `data_pipe` и
завершается с ошибкой.

Для сообщения `MESSAGE_FILE` с помощью `memchr()` проверяется наличие
завершающего символа `\0` внутри массива `file_name`. Без него массив нельзя
безопасно использовать как строку.

Если имя корректное, ребёнок печатает имя полученного файла и ожидаемый
размер файла. Затем создаётся массив для имени копии, и через `snprintf()`
формируется новое имя с окончанием `.copy`. После `snprintf()` проверяется,
удалось ли сформировать имя и поместилось ли оно в выделенный массив.

Затем ребёнок с помощью `open()` создаёт или открывает файл-копию и получает
его дескриптор `copy_fd`. Файл открывается только для записи. Флаг `O_CREAT`
создаёт его при отсутствии, а `O_TRUNC` очищает уже существующий файл перед
записью. Права `0644` разрешают владельцу чтение и запись, а остальным —
только чтение.

Если создать или открыть файл-копию не удалось, ребёнок выводит ошибку,
закрывает дескриптор чтения `data_pipe` и возвращает `EXIT_FAILURE`.

После этого вызывается `receive_file_content()`. В неё передаются дескриптор
чтения из `data_pipe`, дескриптор файла-копии `copy_fd` и ожидаемый размер
файла из `received_metadata.file_size`. Функция получает содержимое из
канала и записывает его в копию. Результат сохраняется в переменной
`receive_result`.

После возвращения из функции ребёнок закрывает `copy_fd`. Дескриптор
`data_read_fd` пока не закрывается, потому что через него может прийти
следующий файл или сообщение `MESSAGE_DONE`.

Затем проверяется, успешно ли закрылся файл-копия и удалось ли
`receive_file_content()` получить всё содержимое. При успехе ребёнок
печатает имя созданной копии и её размер, после чего цикл переходит к
ожиданию следующего сообщения.

Функция `receive_file_content()` выполняется в дочернем процессе. Она
получает содержимое одного файла из канала и записывает его в созданный файл
`.copy`. Функция принимает дескриптор чтения из `data_pipe`, дескриптор
файла-копии и количество байтов, которое ребёнок должен получить.

Внутри создаётся временный буфер размером `DATA_BUFFER_SIZE`, то есть 4096
байтов. Ребёнок не загружает весь файл в память, а получает его частями из
канала и записывает каждый полученный блок в копию.

Переменная `bytes_remaining` первоначально равна полному размеру файла и
хранит количество байтов, которые ещё нужно получить. Цикл работает, пока
это значение больше нуля. Для пустого файла цикл не выполняется, и функция
сразу возвращает успешный результат.

На каждой итерации вычисляется `requested_size`. Если осталось не меньше
размера буфера, функция запрашивает 4096 байтов. Для последнего блока
меньшего размера запрашивается только фактический остаток файла.

Функция `read_all()` пытается получить из канала ровно `requested_size`
байтов и записывает их в `buffer`. Результат чтения сохраняется в переменной
`bytes_read`.

Если `read_all()` возвращает `-1`, произошла системная ошибка чтения, поэтому
ребёнок выводит диагностическое сообщение и возвращает `EXIT_FAILURE`.

Если количество прочитанных байтов не равно `requested_size`, родитель
закрыл канал до передачи всего содержимого. В этом случае файл-копия был бы
неполным, поэтому функция также возвращает `EXIT_FAILURE`.

Полностью полученный блок записывается в файл-копию через `write_all()`. В
неё передаются дескриптор `copy_fd`, адрес буфера и фактическое количество
полученных байтов. `write_all()` гарантирует запись всего блока.

После успешной записи из `bytes_remaining` вычитается `bytes_read`. Цикл
продолжается, пока количество оставшихся байтов не станет равным нулю. Затем
функция возвращает `EXIT_SUCCESS`.

Точный размер файла необходим потому, что канал передаёт непрерывный поток
байтов и не сохраняет границы отдельных сообщений. Ребёнок читает ровно
`file_size` байтов содержимого текущего файла. После этого он понимает, что
следующие байты в канале относятся уже к следующей структуре
`file_metadata`.

После успешного получения и записи содержимого ребёнок печатает имя
созданной копии и её размер. Затем начинается следующая итерация бесконечного
цикла, и ребёнок снова ожидает служебное сообщение от родителя.

Так продолжается, пока не будет получен `MESSAGE_DONE`. При получении этого
сообщения ребёнок выходит из цикла через `break`, закрывает дескриптор чтения
`data_pipe` и возвращает `EXIT_SUCCESS`.
