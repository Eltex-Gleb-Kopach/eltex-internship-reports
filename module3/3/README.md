Функция main() является точкой входа в программу. Она получает количество аргументов argc и массив аргументов argv. Программа проверяет, что пользователь передал ровно один аргумент — базовое имя очередей. После проверки main() вызывает функцию run_p2p_chat() и передаёт ей argv[1], то есть указанное пользователем имя.

В функции run_p2p_chat() сначала проверяется базовое имя очередей. Оно не должно быть пустым или содержать символ / внутри. Затем создаются два символьных массива queue_1_name и queue_2_name, в которые с помощью snprintf() записываются полные имена POSIX-очередей. К базовому имени добавляются окончания _1 и _2.

Создаётся переменная attributes типа struct mq_attr. Это системная структура с параметрами POSIX-очереди. В ней задаётся максимальное количество хранящихся сообщений — 10, и максимальный размер одного сообщения — 1024 байта.

Программа пытается эксклюзивно создать первую POSIX-очередь с помощью mq_open(). Если создание удалось, процесс считается создателем и создаёт вторую очередь. Если первая очередь уже существует, программа открывает обе существующие очереди и работает как второй участник. Если при создании или открытии произошла другая ошибка, программа выводит диагностику и завершается.

После определения роли программа выбирает направление передачи. Создатель принимает сообщения через первую очередь queue_1, а отправляет через вторую queue_2. Второй участник использует очереди наоборот: отправляет через queue_1, а принимает через queue_2.

Поскольку программа сначала проверяет ввод через poll(), а потом читает его через fgets(), для stdin отключается внутренняя буферизация. Это не позволяет fgets() считывать следующие строки заранее, поэтому poll() корректно обнаруживает каждую новую строку.

Сначала создаётся и заполняется структура receiver_context, содержащая очередь приёма и флаги состояния. Затем атомарные флаги устанавливаются в ноль. После этого с помощью pthread_create() создаётся отдельный поток, который начинает выполнять функцию receive_message() и получает адрес структуры receiver. Основной поток продолжает работу и занимается вводом и отправкой, а новый поток параллельно принимает сообщения. Если создать поток не удалось, программа освобождает ресурсы и завершается с ошибкой.

В начале каждой итерации создаётся символьный массив outgoing_message, в который будет записано сообщение пользователя. Затем функция poll() ожидает появление данных в stdin не более 0,1 секунды. Такое ограниченное ожидание позволяет основному потоку регулярно проверять флаг SIGINT и флаг завершения второй стороны.

Если poll() вернула 0, пользователь пока ничего не ввёл и цикл начинается заново. Если возвращено -1, ожидание было прервано сигналом либо произошла ошибка. Положительное значение означает, что со стандартным вводом произошло событие.

Когда данные готовы, функция fgets() читает строку из stdin и записывает её в массив outgoing_message. Затем программа удаляет символ перевода строки и проверяет введённое сообщение.

Если строка оказалась длиннее доступного буфера, её оставшаяся часть считывается и выбрасывается, чтобы она не стала следующим сообщением. Пустые сообщения также не отправляются. Команда /exit отдельно завершает цикл.

Если все проверки пройдены, функция mq_send() помещает сообщение в очередь отправки с обычным приоритетом 1.

После выхода из основного цикла программа устанавливает атомарный флаг local_finished, сообщая своему потоку-получателю о завершении локального ввода. Затем основной поток отправляет второй стороне служебное сообщение FINISH с приоритетом 0. После этого он через pthread_join() ожидает завершения собственного дополнительного потока и проверяет, не произошла ли в нём ошибка. Далее оба дескриптора очередей закрываются, а процесс-создатель дополнительно удаляет очереди. После освобождения ресурсов процесс завершается.

Дополнительный поток в цикле ожидает входящие сообщения через mq_timedreceive(). Ожидание ограничено 0,1 секунды, чтобы поток мог реагировать на SIGINT и завершаться без второй стороны. После получения сообщения поток проверяет его приоритет. Обычное сообщение с приоритетом 1 выводится в терминал, а сообщение с приоритетом 0 считается уведомлением FINISH. В этом случае устанавливается флаг завершения второй стороны, и поток заканчивает работу. Вывод защищён мьютексом, чтобы сообщения дополнительного потока не смешивались с выводом основного потока.

В каждом процессе основной и дополнительный потоки могут одновременно выводить информацию в один терминал. Для синхронизации используется output_mutex. Перед выводом поток захватывает мьютекс через pthread_mutex_lock(), выполняет очистку строки и печать, а затем освобождает его через pthread_mutex_unlock(). Поэтому вывод одного потока не смешивается с выводом другого. Мьютекс действует только между потоками одного процесса и не управляет очередями сообщений.
