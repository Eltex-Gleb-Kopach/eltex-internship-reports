Я выбрал обычное бинарное дерево поиска. Для периодической балансировки
выбрал полную перестройку дерева через отсортированный массив: контакты
копируются в массив симметричным обходом, после чего средний элемент
становится корнем, а из левой и правой половин рекурсивно строятся поддеревья.
Балансировка выполняется после каждых десяти успешных добавлений.

Добавил комментарии в коде, чтобы было проще понять рекурсивные обходы,
вставку, удаление и этапы балансировки.

Также я переделал юнит-тесты под бинарное дерево.

Первый тест проверяет создание и вставку первого узла. Он нужен, чтобы
убедиться, что узел становится корнем дерева, а его указатели left и
right равны NULL.

Второй тест проверяет порядок вставки. Контакт, который меньше корня,
должен попасть в левое поддерево, а больший — в правое. Дополнительно
проверяется количество узлов и правильный порядок всего дерева.

Третий тест проверяет поиск по ID. В нём проверяется существующий ID,
несуществующий ID и недопустимое значение 0.

Четвёртый тест проверяет поиск по Ф.И.О. Проверяется поиск по одному
полю, сочетанию фамилии и имени, отсутствие совпадений и попытка поиска
без единого заполненного критерия.

Пятый тест проверяет удаление листа, то есть узла без потомков. После
удаления проверяется количество оставшихся контактов и порядок дерева.

Шестой тест проверяет удаление узла с одним потомком. Его потомок должен
занять освободившееся место, не нарушив порядок дерева.

Седьмой тест проверяет удаление корня с двумя потомками. Место корня
должен занять наименьший узел правого поддерева, а остальные связи
должны сохраниться.

Восьмой тест имитирует перемещение контакта после редактирования. Узел
отсоединяется, его фамилия изменяется, после чего тот же узел повторно
вставляется в новое место. При этом его ID должен сохраниться.

Девятый тест проверяет загрузку 10 готовых контактов, назначение ID,
количество созданных узлов и запрет повторной загрузки в непустую
телефонную книгу.

Десятый тест специально создаёт вытянутое дерево из семи узлов. После
балансировки его высота должна уменьшиться с семи до трёх, при этом все
контакты, их ID и правильный порядок дерева должны сохраниться.
